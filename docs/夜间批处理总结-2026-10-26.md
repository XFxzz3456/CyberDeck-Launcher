## 二、夜间发生的一次真实数据事故（已修复并恢复）

- **现象**：改名后首次启动，界面模组全空；数据目录出现 `launcher-state.broken-*.json` + 968 字节空状态。
- **真因**：`schema.rs::deserialize_always_empty`（为清空旧 `modpacks` 记录而写）**丢弃反序列化器参数、没消费输入** →
  serde 解析位置错位 → 整个状态文件被判"损坏" → `store.rs` 静默重置为空。**游戏目录里的模组文件没丢，丢的是索引。**
- **修复**：改用 `IgnoredAny::deserialize(deserializer)?` 消费输入；新增回归测试
  `schema::modpacks_cleared_on_load::modpacks_field_is_ignored_but_still_consumed`。
- **恢复**：从 `.broken` 复原 → `mods=195 / loadOrder=125 / modpacks=0 / nexus 引用完整`；修复后启动未再产生新的 `.broken`。
- 复盘全文：`docs/INCIDENT-2026-10-26-state-parse-desync.md`

## 六、本轮踩过的坑（已写进项目记忆）

1. **改目录名会打断 pnpm**：node_modules 软链是绝对路径 → `rm -rf node_modules && pnpm install --offline`；
2. PowerShell 5.1 读无 BOM 的中文 `.ps1` 会乱码 → 迁移改用直接命令；
3. bash heredoc 里 `r"..."` 的反斜杠会被吞成正斜杠 → 路径改写用 `chr(92)`；
4. `shutdown.exe` 的排期与 `schtasks` 都被沙箱策略拦截 → 改用一次性自动任务执行 WMI 关机；
5. serde 自定义 `deserialize_with` **必须消费输入**（见第二节）。
