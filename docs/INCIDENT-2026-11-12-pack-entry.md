# 复盘：整合包入口被藏进「更多」+ 导入入口重复（2026-11-12）

## 现象

用户截图圈出三处：顶部「导入压缩包」、左侧分类栏底部「+ 导入压缩包」、工具栏「更多」菜单里的「整合包」。
诉求两句：整合包是高频操作，不该藏在「更多」里；导入类入口太多、冗余。

## 真因

1. **规则用错了对象**。1.8.0 加整合包功能时沿用了「低频入口一律塞进既有下拉 /『更多』」的旧规则，
   于是「导入方式」下拉里给了「导入整合包…」「导出整合包…」两项，「更多」里又补了一个「整合包」兜底。
   但整合包是**高频主操作**，而且导出/导入本来就是同一个对话框的两个页签 —— 三个入口做的是同一件事。
2. **历史遗留的双入口**。顶部全局栏的「导入压缩包」与侧栏底部 `.rail-import` 绑的是同一个 `onImport`，
   一个动作两处可点；名字又与「整合包」相近，进一步放大混淆。
3. 截图里「自建整合包 ▾」其实是用户自建的**播放集名称**（ProfileMenu），不是功能入口，视觉上又多了一个「整合包」字样。

## 走过的错误假设

第一反应是「在库工具栏加一个常驻『整合包』按钮最直观」。加完立刻复发了 1.8.0 的旧坑：
新按钮多占约 80px，密度档从 `full` 掉到 `compact`，`is-low-frequency` 的「补全」整组被收起，
`check-toolbar.mjs` 点「补全」时元素不可见、30 秒超时。工具栏是实测溢出才降档的紧空间，**不能再塞常驻按钮**。

## 代价 / 新约束

- 入口改放**顶部全局栏**：那里搜索框是弹性宽度、按钮不会随密度档隐藏，三种宽度实测零溢出。
- 窄屏（≤1150px）收起「开始游戏」里的 `Ctrl ↵` 提示来腾空间；快捷键仍可用。
- 工具栏 DOM / CSS 零改动 → 密度档与全部既有断言保持原样，这是这次最省风险的取舍。
- **一个动作一个入口**：整合包的导出/导入共用同一个对话框的两个 tab；普通导入只留顶部一个按钮（空库引导除外）。
- 文案分家：「导入模组」装单个 Mod 压缩包，「整合包」管 `.cdlist` / `.cdpack`。

## 下次第一步查什么

改任何 UI 入口前先做两件事：
1. **数一遍同一动作现在有几个入口**（含下拉、更多、空状态、命令面板），别只盯着要改的那一处；
2. **看目标容器有没有密度档 / 响应式隐藏规则**（`.library-toolbar` 有，`TopBar` 没有）。
   高频入口优先放没有降档机制的容器，而不是默认塞「更多」。

## 验证留痕

`check-modpack.mjs` 新增 6 条去重/常驻断言；`check-toolbar.mjs` 全绿；1440 / 1150 / 1000 三档截图核对无溢出。
