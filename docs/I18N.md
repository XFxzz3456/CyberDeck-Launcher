# i18n 预留架构（占位方案）

> 建立于 2026-10-26。**当前只有中文一份词表，不提供语言切换，也不引入 i18next 等库。**
> 目标只有一个：把「文案」从「代码」里彻底剥离，未来真的要做多语言时不需要再翻 33 个组件。

## 1. 一条规则

**用户可见的文本只能出现在 `src/i18n/zh-CN.ts` 里。** 组件、页面、工具函数一律通过 `t("命名空间.key")` 取值。

「用户可见」包含容易被忘掉的几类：

| 类别 | 例子 |
| --- | --- |
| JSX 文本 | `<button>开始游戏</button>` |
| 属性文案 | `title=`、`placeholder=`、`aria-label=` |
| 动态拼接 | `` `已安装 ${n} 个模组` `` → `t("x.installed", { n })` |
| 模块级常量 | `SETTINGS_TABS` 的 `label`、侧栏 `NAV` 的 `label`／`en` |
| 装饰性英文 | `// OPERATIONS`、`STAGING`、`// DANGER ZONE / HOLD TO CONFIRM` |
| 品牌与版本 | `CYBERDECK`、`MOD LOADER`、`v0.7.0` |

不纳入词表的：`console.error` 等开发者日志、`data-*` 技术标识、路径、文件名、正则、测试夹具、`mock.ts` 的假数据。

## 2. 文件结构

```
src/i18n/
  zh-CN.ts   ← 唯一文案来源（嵌套对象，as const）
  index.ts   ← t(key, vars?) 占位实现 + 类型契约 + tDyn 逃生口
scripts/check-i18n.mjs  ← 守卫：扫描漏网的硬编码中文
docs/I18N.md            ← 本文件
```

### `t` 的契约

```ts
import { t } from "../i18n";

t("topBar.launch");                          // → "开始游戏"
t("topBar.bellUnread", { count: 3 });        // → "3 条未读动态"
tDyn(`settings.tabs.${id}`);                 // 动态 key（类型不校验，仅拼装场景）
```

- **key 写错会在 `tsc --noEmit` 阶段报错**：`MessageKey` 是由词表结构递归推导出的字面量联合，不是 `string`。
- 插值占位符统一 `{name}`；缺少变量时原样保留 `{name}`，方便一眼看出漏传。
- key 在词表里不存在时**返回 key 本身**（dev 环境额外 `console.warn`），界面上会直接看到 `topBar.launch` 这种错位，而不是静默空白。
- 不使用 React Context：`t` 必须在模块级常量、事件回调、class 组件里都能同步调用。真要做语言切换时再加一层读 locale 的 Provider。

## 3. 命名空间约定

| 命名空间 | 用途 |
| --- | --- |
| `app.*` | 品牌名、副标题、版本、代号 |
| `common.*` | 跨页面复用的动作词与通用提示（保存/取消/确认/关闭/加载中…） |
| `<页面或组件名>.*` | 该页面独有文案，如 `topBar.*`、`sidebar.*`、`settings.*` |
| `errorBoundary.*` | 兜底界面文案 |
| `danger.*` | 危险操作按住确认组件 |

新增文案时**先找 `common.*` 有没有现成的**，有就复用，避免「关闭」在三处写法不同。

## 4. 守卫脚本

```bash
npm run i18n:check    # 进度看板：按文件列出剩余硬编码条数，退出码 0
npm run i18n:list     # 逐条打印 file:line 与片段
npm run i18n:gate     # 门禁模式：还有硬编码就退出码 1
npm run i18n:unused   # 反向检查：词表里存在、但源码从未引用的死条目
```

行为细节：

- 递归扫描 `src/**/*.ts(x)`，排除 `src/i18n/zh-CN.ts`（词表本身）与 `mock.ts`（开发假数据）。
- 先剥离块注释与行注释再判定，注释里的中文不算违规。
- 豁免有两种写法，只用于**真正不该翻译**的文本（开发者日志、持久化数据值、检索关键词）：
  - 行内：`// i18n-ignore`
  - 区块：`// i18n-ignore-start` … `// i18n-ignore-end`（整张数据表用，如命令面板的检索关键词表）
- `--unused` 用自定界 token 匹配（`` /[`"']key[`"']/ ``）而不是「成对引号」正则：一行里有多个字符串（尤其 `: ""` 空串）时引号配对会错位，把 `t("palette.modDeployed")` 误判成没被引用。

**文案已全量归零，`i18n:gate` 可以接进 CI / `npm run build` 前置**（现在不会把构建打红）。

### 两类中文（改代码前必须先分清）

**A 类 · 纯文案** → 搬进词表，组件里 `t()` 取值。

**B 类 · 数据值** → **一个字都不能改**，只做「数据值 → 文案」的渲染层映射：

| B 类数据 | 位置 | 为什么不能改 | 显示映射 |
| --- | --- | --- | --- |
| `"全部" \| "已启用" \| "框架" \| "玩法" …` | `types.ts` 的 `CATEGORIES` | 持久化进 `launcher-state.json` 的 `mods[].category`，同时是筛选比较值 | `categoryLabel(value)` |
| `InstallLayout`（`gameRoot` / `archive` / …） | `types.ts` | 持久化 + 布局判定 | `LAYOUT_LABEL_KEY[layout]` |
| 主题预设名与说明 | `lib/theme.ts` | 预设 id 参与主题持久化 | 字段存 `labelKey` / `detailKey`（`MessageKey` 类型） |
| 集合条目状态 | `lib/collection.ts` | 后端返回的状态码 | `COLLECTION_STATUS_LABEL[status]`（值为 `MessageKey`） |
| 前置依赖原因 | `lib/dependencies.ts` | 与框架 id 绑定 | 字段 `reasonKey` |
| AI 服务商名 / 密钥提示 / 弃用说明 | `lib/aiPresets.ts` | 与 preset id 绑定 | 字段 `labelKey` / `keyHintKey` / `messageKey` |
| 命令面板检索关键词 | `CommandPalette.tsx` | 用户用中文搜命令，属检索索引 | 区块 `i18n-ignore`，多语言时按语言各备一份 |

`categoryLabel()` 的对照表用**中文数据值做键**（`{ "框架": "category.framework" }`），因为它的输入就是中文数据值；缺映射时**原样返回入参**，绝不把 `category.xxx` 这种裸 key 漏到界面上。

## 6. 并行迁移与合并流程

多人 / 多代理同时迁移时，**不允许各自改 `zh-CN.ts`**（并发写必冲突）。流程是：

1. 每组只改自己负责的组件，并把新增词条写成 `.i18n-parts/<组名>.json`，格式是扁平点路径：

   ```json
   { "settings.stagingMoved": "暂存区已迁移到 {path}" }
   ```

2. 由一人执行 `npm run i18n:merge` 合并。脚本是**幂等**的，并且会主动报错：
   - 上级节点已是字符串（`a.b` 与 `a.b.c` 并存）；
   - 同 key 不同值（多半是两个组各写了一份措辞）。
3. 合并后跑 `tsc --noEmit`：任何一个组写错 key，这里会一次性全暴露（`MessageKey` 是字面量联合）。
4. 最后 `npm run i18n:gate && npm run i18n:unused` 双向归零。

### 文案基准：只能是「抽取当时的源码」

抽取只是**搬运**，不改措辞。但搬运完想验证「有没有被改过」时，**基准必须是抽取前那一刻的源码**，不能拿更早的历史清单/审查快照：

- 2026-10-27 就踩过这个坑：拿 r7 留下的 `文案全量清单.csv` 逐字比对，把 13 处更短的文案判成「抽取时被改短」，全部"恢复原文"——实际那些更短的版本来自**另一个会话的「全局文案去 AI 味」**，清单是它动手之前的快照，方向完全反了，事后全部回退。
- 同理，UI 回归脚本里的中文断言也是「快照」：文案一改，`getByRole(..., { name: /旧文案/ })` 就会超时。**先确认是源码变了还是脚本旧了**，不要顺手把文案改回去迁就测试。
- 批量核对陈旧断言的办法：把脚本里所有中文正则与 `name:` 断言提出来，取最长连续中文片段去词表里查，一次列全。

## 7. 未来接真库的四步

1. `src/i18n/zh-CN.ts` → `src/locales/zh-CN.json`（结构不变，直接 `JSON.parse`）。
2. 新增 `src/locales/en-US.json` 等，key 集合必须与 zh-CN 完全一致（可用 `MessageKey` 做编译期比对）。
3. 把 `src/i18n/index.ts` 的 `t` 改为调用 `i18next.t`（或 FormatJS），**其余代码零改动**。
4. 语言切换：外层加 `LocaleProvider` 存当前 locale，切换后触发一次根级 re-render；模块级常量（`NAV`、`SETTINGS_TABS`、`SORTS`）需要在 locale 变化时重建，或改为在组件内用 `useMemo` 计算。

## 8. 已知遗留（都不影响当前单语运行）

1. **结构化文案被拆段**：`confirm.restore.detailPrefix` / `detailMiddle` / `detailSuffix` 这类是为了在句子中间嵌 `<code>r6/config</code>` 而拆的。中文语序没问题，但换成语序不同的语言（如英语、日语）时需要重排，届时应改成「带占位符的富文本」方案（`<code>{0}</code>` 之类），而不是继续拆段。
2. **B 类数据值的翻译**：`categoryLabel` 只解决「显示」，如果未来要让**导出/备份文件**里的分类也随语言变，就得做稳定 id + 迁移，那是独立工程（会动持久化格式）。
3. **`toLocaleTimeString("zh-CN")`**（`TopBar` 时钟、`TaskCenter` 时间）的 locale 标识是硬编码的，接真库时改成读当前 locale。
4. **`src/lib/format.ts` 的分类 switch** 仍在按中文数据值分支，改分类体系时要同步改它。
