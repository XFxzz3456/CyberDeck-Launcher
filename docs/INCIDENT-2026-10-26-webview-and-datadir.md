# 事故复盘：外链打不开 + API Key「时有时无」（2026-10-26）

> 影响版本：0.7.0 当日构建（10-25 23:23 起）
> 耗时：约 1 小时 / 6 轮错误假设
> 结论先行：**两个独立故障被同一次"环境变化"掩盖，导致每一步修复都像成功**
>
> ⚠️ **本文件的根因结论已被推翻**：真正的单一根因是「exe 所在目录携带 Low 完整性标签」，
> 见 `docs/INCIDENT-2026-10-26-low-integrity-rootcause.md`。本文件保留作为**误判过程记录**，
> 其中的排查方法仍有效，但"真因"一节请以新文件为准。

---

## 1. 现象

1. 启动器里所有「打开浏览器」按钮（获取 Key、打开 Nexus 页）点了没反应、也不报错；
2. 非管理员启动时提示需要重新填 Nexus API Key；
3. 管理员启动时 Key 却在（且能跳转）。
4. 通知铃铛角标点开后仍显示、且被切掉一角（另一独立小 bug）。

## 2. 真因

| 故障 | 真因 |
|---|---|
| 跳转静默失效 | `open` crate 当晚随 `cargo update` 升到 5.4.5，Windows 默认 launcher 链从 `cmd /c start` 改为 `powershell(Start-Process) → explorer.exe`，且 `that_detached` 只观察 250ms，"成功"不代表浏览器真被拉起 → 静默假成功 |
| 管理员模式下能跳 | 用户的 Edge 实例是**提权**运行的，普通权限进程的 URL 交接被 UIPI 拦截；两边权限一致时才通 |
| Key 时有时无 | 启动器进程（普通启动时）**写 `%APPDATA%\com.arol.cyberdeck` 被拒（os error 5）**——该目录 ACL 为 Everyone 完全控制、同用户普通 PowerShell 可写，故为**进程令牌受限**所致。旧代码用 `Store::load(preferred)` 失败即静默回退到 exe 同级 `cyberdeck-data`，于是同一台机器并存两套状态，密钥只在其中一套 |
| 角标不消失 | `badgeCount = activities.length + updateCount`，没有已读态；点开也不改任何状态 |
| 角标显示不全 | `.btn` 带 `clip-path`，角标是按钮内的绝对定位子元素 → 被裁掉一角 |

## 3. 我们走错的四步（最有价值的部分）

1. **把"依赖升级"当成唯一原因**：换 `shellexecute-on-windows` feature 后行为变了（出现了 Edge 提权弹框），于是误判为"修好了，只是 Edge 有问题"。
2. **把"管理员可用"当成解法**：加 `requireAdministrator` 清单 —— 实际是让问题被权限一致"掩盖"，同时引入新代价（浏览器被提权、UIPI 阻断拖拽）。
3. **把"目录不统一"当根因**：改成读 `%APPDATA%` 环境变量 —— 日志显示路径解析完全正确，但**写入被拒**，说明真正卡点在权限，不在路径。
4. **每轮只验证"用户说好了/没好"**：用户的观察在两个变量（权限、数据目录）同时变化时无法区分归因。

**教训：一次只改一个变量；每轮修复必须能说清"哪个观测值变了"。**

## 4. 落地成规则（写代码时默认遵守）

### 4.1 外部依赖
- `cargo update` / 依赖升级后，必须回归验证**系统集成类行为**：打开外链、打开目录、文件关联、通知、拖拽。
- 依赖版本锁定：系统集成相关 crate（`open`、`opener`）升级要走单独提交 + 手测，不随日常 `update` 漂移。
- 对"打开外链"这类操作，**优先用 `ShellExecuteW`（`shellexecute-on-windows`）**，它的返回值语义明确；不要用默认的命令拼接链。

### 4.2 路径与数据目录
- 取系统路径**禁止依赖环境变量**（`%APPDATA%`/`%USERPROFILE%` 可能被改写或与令牌不匹配），用 `SHGetKnownFolderPath`。
- 目录可用性判断必须**写探测**（mkdir + 写临时文件），不能只看 `is_dir()` 或读权限。
- **禁止静默回退到另一个目录**：多目录并存 = 状态分裂 = 用户数据"消失"。回退必须写日志，且策略要保证同一机器上不同权限的启动方式落到**同一目录**。
- 数据迁移一律"**补齐不覆盖**"；`secrets`（DPAPI 密文）可跨目录复制，与权限无关。

### 4.3 权限
- 不要用"整程序提权"解决局部访问问题：会连带破坏 UIPI 相关交互（拖拽、剪贴板、浏览器交接）。
- 提权程序打开外链必须**转交 `explorer.exe`**（恒为 medium IL），避免把浏览器提成管理员。

### 4.4 可观测性（GUI 应用红线）
- 无控制台时 `eprintln!` 等于没有日志。关键启动路径必须有**落地日志**（本项目管理 `startup.log`：时间/是否提权/数据目录/解析依据/写探测结果/错误码）。
- 观测点要能区分**分支**：本事故的突破点就是"`probe=write_err(拒绝访问)`"这一行。

### 4.5 UI 状态
- 「未读」必须有**持久化的已读时间戳**，否则红点永久存在；角标不要放在带 `clip-path` 的容器里。

## 5. 诊断手法（可复用）

- 先分层判定：系统层是否正常（`Win+R` / 普通进程 `Start-Process`）→ 应用层是否调用到（有无 toast/日志）→ 系统调用是否真成功（返回值语义）。
- 对照实验：同一操作分别用「普通权限 PowerShell」「被测进程」执行，差异即令牌/权限问题。
- 文件系统类问题：ACL（`Get-Acl`）+ 所有者 + 属性 + **实际写探测** 四件套，缺一不可。

## 6. 遗留与待办

- 待确认：为什么普通启动的启动器进程写入自身 `%APPDATA%` 会被拒（疑似外部安全软件/受限令牌），需观察 `startup.log` 中的 `elevated=false probe=write_err` 是否复现。
- 现策略（02:17）：数据目录优先取已存在的 exe 同级 `cyberdeck-data`，保证两种权限都用同一套数据。
- 未完成：exe 同级的 NSIS 安装场景要验证该目录是否可写（安装到 Program Files 时不可写，需回退 `%APPDATA%`）。
